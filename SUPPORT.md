# Support

This page explains how to get help with SteveRequests.

## Bugs

For reproducible bugs, open a GitHub Issue using the bug report template:

<https://github.com/PurgeCityProjects/StevesRequests/issues/new/choose>

Please include:

- SteveRequests version or release artifact name, if one exists.
- Operating system or runtime environment.
- Whether the issue involves backend startup, PostgreSQL/database access, Second Life/OpenSim scripts, device bootstrap/heartbeat, tip jars, rental terminals, adboards, Discord integration, media streams, reporting, or release packaging.
- Expected behavior.
- Actual behavior.
- Steps to reproduce the issue.
- Relevant logs or error messages with secrets removed.
- Screenshots if they help explain the issue.

Before posting logs or screenshots, remove credentials, API keys, tokens, database passwords, Discord webhook URLs, private tunnel URLs, avatar/payment records that are not needed for the report, personal information, and any other sensitive details.

## Feature Requests

For feature requests, open a GitHub Issue using the feature request template:

<https://github.com/PurgeCityProjects/StevesRequests/issues/new/choose>

Please describe the problem or use case first, then the behavior you would like to see.

## Public Issue Safety

GitHub Issues are public. Do not post:

- Passwords or recovery codes.
- API keys, manager keys, access tokens, or OAuth-style secrets.
- Database credentials, `.env` files, or database dumps.
- Discord webhook URLs or private integration configuration.
- Private tunnel URLs for development deployments.
- Private customer, user, resident, avatar, payment, rental, or staff-session data.
- Full logs that include sensitive information.
- Security vulnerability details that could be exploited before a fix is available.

## Known Public-Release Limitations

No verified public installer, packaged runtime, or application-level release version exists yet. Until the first real release is published, support requests may need to distinguish between public release documentation and private development/deployment details.

## Security Issues

For suspected security vulnerabilities, follow [SECURITY.md](SECURITY.md) instead of opening a public issue.
